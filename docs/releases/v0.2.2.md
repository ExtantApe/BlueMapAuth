Follow-ups from the second security review of the map (K70, 2026-11-24). Install it before any map goes on a server with kids' worlds.

## What changed

- **Players in another world are never sent.** BlueMap marks them "foreign". With its `hide-different-world` set to false, a player you may reach who is standing in a world you can't enter, such as a kids' world, used to have their position sent under your map. Now they're left out, and a flag that isn't a plain false counts as foreign.
- **A player's head picture shows only for players you may see.** It used to tell anyone signed in whether a player had ever joined, and show their skin.
- **Any capitalisation of `live` is treated as live,** so `Live/players.json` can't skip the filter if a later BlueMap matches paths loosely. BlueMap 5.29 already answers those with "not found".
- **Real sign-ins no longer count toward the site-wide limit.** Only failed tries do, so a few addresses signing in normally can't lock everyone else out for a minute. Every try still counts toward each visitor's own limit.
- **A trusted-proxy entry that isn't an address or address/prefix is refused when the plugin loads,** never on each request.

## Installing over 0.2.1 or 0.2.0

With the server stopped, swap in `BlueMapAuth-0.2.2.jar`. Nothing else changes.

## Tested

38 unit and HTTP tests, including foreign players, head pictures for seen and unseen players, mixed-case `live`, the site-wide limit with good and failed tries, and bad proxy entries. Bots on a throwaway Paper 26.1.2 server with the real BlueMap 5.29, LuckPerms, Mayor 0.8.0 and WelcomeWagon 0.6.1: 27/27 direct, 28/28 through a throwaway Caddy running the staged map site block, and 8/8 without Mayor and LuckPerms. The raw path check now also sends mixed-case `live` paths and an unseen player's head picture. Not yet tested behind the real public address.
