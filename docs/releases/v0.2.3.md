Two small follow-ups from Infrastructure's check of 0.2.2 (K70, 2026-11-24).

## What changed

- **A player entry with no "foreign" flag is left out,** as the 0.2.2 notes promised. BlueMap 5.29 always writes the flag, so this only matters if a later BlueMap stops.
- **A working map link always signs in,** even while junk tries have filled the site-wide limit. Before, a few addresses sending junk could lock real players out for a minute. Failed tries are still slowed once the limit is full, and every try still counts toward each visitor's own limit. The links' 256 random bits are what stop guessing.

## Installing over 0.2.2, 0.2.1 or 0.2.0

With the server stopped, swap in `BlueMapAuth-0.2.3.jar`. Nothing else changes.

## Tested

40 unit and HTTP tests, including an entry with no flag and a real sign-in after 70 junk tries from five addresses. The direct bot run against the real BlueMap 5.29 passed 27/27 on Paper 26.1.2. The Caddy and fail-closed runs weren't repeated; 0.2.2 passed both and nothing they check changed.
